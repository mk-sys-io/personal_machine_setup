# TypeScript tooling (machine-wide)

Canonical source of truth for machine-wide TS/JS format, lint, typecheck.
If a config and this doc disagree, fix the doc in the same commit — drift
is a bug. Keep terse: reference configs by path, never restate them.
Delete stale lines rather than appending history. No `plans/` references —
that directory is gitignored and may not exist on another machine.

## Three-layer model

- **Formatter never blocks** — auto-fix on save/commit (Biome 2.6.6).
- **Typecheck + linter block** — commit hook; `tsc` is the only automatic
  type gate.
- **Skill is judgment** — command ladder + non-negotiables, loaded on demand.

## What runs when

| Trigger | Command | Owning path |
|---|---|---|
| Editor save | `biome format` (external) | `dev/zed/settings.json` |
| Editor save (`.md`) | `prettier` (Zed default) — Biome force-ignores `*.md` | `dev/zed/settings.json` |
| Agent edit | format-on-write via adapter; no type gate | `dev/opencode/deploy/opencode.jsonc` |
| Agent edit (wire 4) | *not implemented* | — |
| Commit | `biome check --write <staged paths>` (repo-root cwd) + `tsc --noEmit -p .` | `dev/git/pre-commit` |
| On demand | `biome check --write` → `tsc` → `oxlint --type-aware` | `dev/skills/typescript-lint/SKILL.md` |

## Config layout

| Path | Role |
|---|---|
| `dev/biome/shared.json` | source of truth: formatter, linter, excludes |
| `~/.config/biome/biome.json` | deployed copy; Biome's last-resort fallback (cwd → parents → config home) |
| `<repo>/biome.json` | generated by `init`: `root: true`, `vcs.useIgnoreFile`, absolute `extends` → shared file |

The shared file carries no `root` and no `vcs` key — both are path-dependent.
`$HOME/biome.json` must never exist: it makes `$HOME` the project root, so every
run walks the whole home tree (measured: 5.4 s for one file, 7.3 GiB LSP RSS).
`!!` excludes stop indexing entirely; that, not the glob count, is what bounds
memory. Inside a repo with a generated config, `.gitignore` is authoritative for
traversal **and** explicitly passed paths.

## Adding a repo

Run `init`. It writes `biome.json` only where missing and only inside a git work
tree (Biome hard-fails on `vcs.useIgnoreFile` without one); an existing
`biome.json`/`biome.jsonc` is never modified. `tsconfig.json` is always required
for typecheck (root tsconfig only in the hook). Typed lint needs a repo
`tsconfig.json` (auto-discovered).

## Language coverage

| Language | Biome |
|---|---|
| JS / TS / JSX / TSX | parse · format · lint |
| JSON / JSONC | parse · format · lint |
| CSS / SCSS | parse · format · lint; `dotfiles/**/*.css` force-ignored (GTK dialect) |
| YAML, GraphQL | parse · format · lint |
| Vue / Svelte / Astro | experimental (2.3+, needs `html.experimentalFullSupportEnabled`) |
| HTML | lint only; format is experimental + explicit opt-in |
| Markdown | capable, but force-ignored — Prettier owns `.md` |
| GritQL | parse only |
| Python / Rust / Java / Go / shell | silently skipped (no parser) |

`dotfiles/**/*.css` is GTK 3 stylesheets, not web CSS: `@define-color` +
`@name` refs and widget nodes as type selectors are documented GTK extensions
that no web-CSS parser accepts (Sass likewise refuses them, sass/sass#3896).
Measured 2026-11-15: 149 false diagnostics across 4 files, while GTK 3's own
`Gtk.CssProvider` loads all four with zero errors — so Biome was 100% wrong.
Not reached by the hook (no `css` in `dev/git/pre-commit:20`) nor by Zed save.

## Tier policy

| Tier | Rules | Enforcement |
|---|---|---|
| Block | tsc strict set; Biome correctness recommended at error (noUnusedImports, noUnusedVariables); suspicious/noExplicitAny, noTsIgnore → error; nursery noFloatingPromises, noMisusedPromises, useExhaustiveSwitchCases, noUnsafeReturn, noUnsafeTypeAssertion → error | hook (tsc); skill (biome `--error-on-warnings`) |
| Typed | `oxlint --type-aware`: no-unsafe-assignment, no-unsafe-call, no-unsafe-member-access, no-unsafe-return, no-unsafe-argument, no-unsafe-type-assertion, no-floating-promises, no-misused-promises (verified on 1.92.0) | skill only |
| Auto-fix (safe) | format, import order, unused imports, prefer-const, trivial simplifications | editor save, adapter formatter, hook |
| Warn/off | noExcessiveCognitiveComplexity → warn; max-*, naming, sort-keys, no-console → off; noNonNullAssertion → warn | never blocks |

## Known gaps

- Typed lint is skill-gated only (8 rules); not in hook or save.
- No post-write feedback exists yet (wire 4 designed, not implemented).
- OpenCode V2 ignores `lsp`; the block was deleted — do not re-add.
- The git hook fires only on commit; a non-committing agent gets no automatic type gate.
- Never suppress to pass: no `any`/`as unknown as`/`void` laundering, no
  `@ts-ignore` without reason, no config edits, no test deletion.
